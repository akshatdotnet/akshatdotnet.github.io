C# Fundamentals Beginner
Variables, data types, operators, control flow, methods, arrays, collections

C# is a strongly-typed, object-oriented language that runs on the .NET runtime (CLR). Every value has a known type at compile time, which enables type-safety and excellent tooling.

C# — Variables & Collections
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        // Value types
        int employeeId = 1001;
        decimal salary = 85_000.50m;   // _ separator improves readability
        bool isActive = true;

        // Reference type — string is immutable
        string name = "Jane Doe";

        // C# 12 — primary constructors and collection expressions
        List<string> departments = ["Engineering", "Finance", "HR"];
        Dictionary<string, decimal> salaryBand = new()
        {
            ["Junior"] = 45_000m,
            ["Senior"] = 90_000m,
            ["Lead"]   = 130_000m,
        };

        // Null-safe access with ?.
        string? middleName = null;
        int nameLength = middleName?.Length ?? 0;

        // Pattern matching (C# 9+)
        string category = salary switch
        {
            < 50_000m  => "Entry Level",
            < 100_000m => "Mid Level",
            _           => "Senior Level"
        };

        // String interpolation
        Console.WriteLine($"{name} [{employeeId}] — {category}");

        // foreach with index
        foreach (var (dept, idx) in departments.Select((d, i) => (d, i)))
            Console.WriteLine($"  {idx + 1}. {dept}");
    }
}
Real-World Use Case
Employee onboarding systems: validating incoming HR data (age ≥ 18, salary within band, department exists) before persisting to the database. Collection expressions reduce boilerplate in test data factories.
Best Practices
Use const for values that never change and readonly for instance values set once in constructors. Prefer var when the type is obvious from the right-hand side. Never use ArrayList — always prefer generic collections.
Common Mistakes
Using == on strings with StringComparison omitted leads to locale bugs. Concatenating strings in a loop with + instead of StringBuilder causes O(n²) allocations.
Interview Tips
Be ready to explain the difference between value types (stack) vs reference types (heap), boxing/unboxing overhead, and why string is immutable. Interviewers love the Span<T> question for senior roles.

C# — OOP / Polymorphism
// Interface defines a contract
public interface IPayable
{
    decimal CalculateNetPay(int hoursWorked);
}

// Abstract base — shared behaviour without instantiation
public abstract class Employee : IPayable
{
    public int    Id     { get; init; }
    public string Name   { get; init; }
    protected decimal BaseSalary { get; init; }

    // Template Method pattern — subclasses override CalculateBonus
    public decimal CalculateNetPay(int hoursWorked) =>
        BaseSalary + CalculateBonus(hoursWorked);

    protected abstract decimal CalculateBonus(int hoursWorked);

    public override string ToString() =>
        $"[{GetType().Name}] {Name} (ID: {Id})";
}

// Concrete subclasses
public sealed class FullTimeEmployee(int id, string name, decimal salary)
    : Employee
{
    public int Id       { get; } = id;
    public string Name  { get; } = name;
    protected decimal BaseSalary { get; } = salary;

    protected override decimal CalculateBonus(int hours) =>
        hours > 160 ? BaseSalary * 0.10m : 0m;
}

public sealed class ContractEmployee(int id, string name, decimal rate)
    : Employee
{
    protected override decimal CalculateBonus(int hours) => rate * hours;
}

// Polymorphic usage — works for ALL employee types
IEnumerable<IPayable> payroll = GetPayroll();
decimal totalPayout = payroll.Sum(e => e.CalculateNetPay(hoursWorked: 170));

// Immutable value object using record
public record Money(decimal Amount, string Currency = "USD")
{
    public Money Add(Money other) =>
        Currency != other.Currency
            ? throw new InvalidOperationException("Currency mismatch")
            : this with { Amount = Amount + other.Amount };
}
Best Practices
Favour composition over inheritance for reuse. Seal classes you don't intend to be subclassed — it gives the JIT optimisation hints. Use record for immutable DTOs; they give value-equality and ToString() for free.
Interview Tips
Classic question: "Interface vs Abstract Class?" Key points — multiple interface inheritance, interfaces have no state, abstract classes can have constructors and protected members. Also know default interface methods (C# 8+).

C# — Async / Await Best Practices
public class OrderService(IOrderRepository repo, IEmailService email)
{
    // Always pass CancellationToken down the call chain
    public async Task<Order> PlaceOrderAsync(
        OrderRequest request,
        CancellationToken ct = default)
    {
        // Validate first — synchronous, no await needed
        ArgumentNullException.ThrowIfNull(request);

        // Parallel I/O — run together, await both
        var (inventory, customer) = await (
            repo.GetInventoryAsync(request.ProductId, ct),
            repo.GetCustomerAsync(request.CustomerId, ct)
        ).WhenAll();

        if (inventory.Stock < request.Quantity)
            throw new InsufficientStockException(request.ProductId);

        var order = Order.Create(request, customer, inventory);
        await repo.SaveAsync(order, ct);

        // Fire-and-forget — do NOT await, use background task
        _ = Task.Run(() => email.SendConfirmationAsync(order), ct);

        return order;
    }
}

// NEVER do this — sync-over-async deadlocks in ASP.NET
// var result = someAsyncMethod().Result;  ❌

// PREFER ConfigureAwait(false) in library code
public static async Task<string> FetchDataAsync(string url)
{
    using var client = new HttpClient();
    return await client.GetStringAsync(url).ConfigureAwait(false);
}
Performance Tips
Use IAsyncEnumerable<T> for streaming large datasets instead of loading everything into memory. Prefer ValueTask over Task for hot paths that often complete synchronously. Use ArrayPool<T> and Span<T> to avoid heap allocations in tight loops.
Common Mistakes
Forgetting ConfigureAwait(false) in library code causes deadlocks. Materialising an IQueryable before filtering (calling ToList() early) loads the entire table. Capturing HttpContext in a background task after the request ends throws ObjectDisposedException.

SQL — Aggregation & JOINs
-- NEVER use SELECT * in production
SELECT
    e.EmployeeId,
    e.FullName,
    d.DepartmentName,
    e.Salary,
    e.HireDate,
    DATEDIFF(YEAR, e.HireDate, GETDATE()) AS YearsOfService
FROM  dbo.Employees  AS e
INNER JOIN dbo.Departments AS d ON d.DepartmentId = e.DepartmentId
WHERE  e.IsActive = 1
  AND  e.Salary BETWEEN 50000 AND 200000
ORDER BY e.Salary DESC;

-- Departmental payroll summary
SELECT
    d.DepartmentName,
    COUNT(e.EmployeeId)        AS HeadCount,
    AVG(e.Salary)              AS AvgSalary,
    SUM(e.Salary)              AS TotalPayroll,
    MAX(e.Salary)              AS TopSalary
FROM  dbo.Employees  AS e
JOIN  dbo.Departments AS d ON d.DepartmentId = e.DepartmentId
WHERE  e.IsActive = 1
GROUP BY d.DepartmentName
HAVING COUNT(e.EmployeeId) > 5      -- Only departments with 5+ staff
ORDER BY TotalPayroll DESC;

-- LEFT JOIN — find employees WITHOUT a manager (NULL check)
SELECT e.FullName, m.FullName AS ManagerName
FROM  dbo.Employees AS e
LEFT  JOIN dbo.Employees AS m ON m.EmployeeId = e.ManagerId
WHERE  m.EmployeeId IS NULL;  -- These are top-level employees
Best Practices
Always use schema-qualified names (dbo.TableName). Use meaningful aliases. Never use SELECT * — it breaks when columns are added. Use BETWEEN inclusively and be aware of implicit type conversions killing index scans.
Interview Tips
Explain the logical order of SQL execution: FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT. Common trap: WHERE can't reference column aliases defined in SELECT — use a subquery or CTE.

Stored procedures, CTEs, window functions, indexes, transactions, performance tuning
SQL — CTE + Window Functions
-- Window functions — salary ranking per department
WITH DeptRanks AS
(
    SELECT
        EmployeeId,
        FullName,
        DepartmentId,
        Salary,
        RANK()      OVER (PARTITION BY DepartmentId ORDER BY Salary DESC) AS SalaryRank,
        DENSE_RANK()OVER (PARTITION BY DepartmentId ORDER BY Salary DESC) AS DenseSalaryRank,
        LAG(Salary) OVER (PARTITION BY DepartmentId ORDER BY HireDate)   AS PreviousSalary,
        AVG(Salary) OVER (PARTITION BY DepartmentId)                     AS DeptAvgSalary
    FROM dbo.Employees
    WHERE IsActive = 1
)
SELECT * FROM DeptRanks WHERE SalaryRank <= 3;  -- Top 3 per dept

-- Recursive CTE — org hierarchy
WITH OrgChart AS
(
    -- Anchor: top-level managers
    SELECT EmployeeId, FullName, ManagerId, 0 AS Level
    FROM   dbo.Employees
    WHERE  ManagerId IS NULL

    UNION ALL

    -- Recursive: walk down the tree
    SELECT e.EmployeeId, e.FullName, e.ManagerId, oc.Level + 1
    FROM   dbo.Employees AS e
    JOIN   OrgChart      AS oc ON oc.EmployeeId = e.ManagerId
)
SELECT REPLICATE('   ', Level) + FullName AS HierarchyView, Level
FROM   OrgChart
ORDER BY Level, FullName
OPTION (MAXRECURSION 10);  -- guard against infinite loops
SQL — Production Stored Procedure
CREATE OR ALTER PROCEDURE dbo.usp_TransferEmployee
    @EmployeeId     INT,
    @NewDeptId      INT,
    @TransferDate   DATE,
    @RequestedBy    NVARCHAR(100),
    @AffectedRows   INT OUTPUT
AS
BEGIN
    SET NOCOUNT ON;
    SET XACT_ABORT ON;   -- auto-rollback on error

    BEGIN TRY
        BEGIN TRANSACTION;

            -- Validate employee exists and is active
            IF NOT EXISTS
            (
                SELECT 1 FROM dbo.Employees
                WHERE  EmployeeId = @EmployeeId AND IsActive = 1
            )
                THROW 50001, 'Employee not found or inactive.', 1;

            -- Update employee record
            UPDATE dbo.Employees
            SET    DepartmentId = @NewDeptId,
                   ModifiedAt   = SYSDATETIME(),
                   ModifiedBy   = @RequestedBy
            WHERE  EmployeeId   = @EmployeeId;

            SET @AffectedRows = @@ROWCOUNT;

            -- Audit trail
            INSERT INTO dbo.EmployeeAudit
                   (EmployeeId, Action, Detail, CreatedAt, CreatedBy)
            VALUES (@EmployeeId, 'TRANSFER',
                    CONCAT('Dept changed to ', @NewDeptId, ' on ', @TransferDate),
                    SYSDATETIME(), @RequestedBy);

        COMMIT TRANSACTION;
    END TRY
    BEGIN CATCH
        IF XACT_STATE() <> 0 ROLLBACK TRANSACTION;
        THROW;   -- re-raise to caller
    END CATCH
END;
Performance Tips
Create indexes on columns that appear in WHERE, JOIN, and ORDER BY clauses — in that priority order. Avoid functions on indexed columns in WHERE (e.g. YEAR(HireDate) = 2024 kills the index; use a range instead). Use SET STATISTICS IO ON to measure logical reads, not just execution time.
Interview Tips
Explain the difference between RANK(), DENSE_RANK(), and ROW_NUMBER(). Know when to use a CTE vs a subquery (readability, recursion, multiple references). Always discuss XACT_ABORT ON in stored procedures.

C# — EF Core DbContext & Repository
// Entity with Fluent API config inside IEntityTypeConfiguration
public class Employee
{
    public int       Id           { get; private set; }
    public string    Name         { get; private set; } = null!;
    public decimal   Salary       { get; private set; }
    public int       DepartmentId { get; private set; }
    public Department Department  { get; private set; } = null!;

    private Employee() { }  // EF needs a private ctor

    public static Employee Create(string name, decimal salary, int deptId)
    {
        ArgumentException.ThrowIfNullOrWhiteSpace(name);
        return new Employee { Name = name, Salary = salary, DepartmentId = deptId };
    }
}

public class EmployeeConfiguration : IEntityTypeConfiguration<Employee>
{
    public void Configure(EntityTypeBuilder<Employee> builder)
    {
        builder.ToTable("Employees", "dbo");
        builder.HasKey(e => e.Id);
        builder.Property(e => e.Name).HasMaxLength(150).IsRequired();
        builder.Property(e => e.Salary).HasColumnType("decimal(18,2)");
        builder.HasIndex(e => e.Name);  // Index frequently searched columns
        builder.HasOne(e => e.Department)
               .WithMany(d => d.Employees)
               .HasForeignKey(e => e.DepartmentId)
               .OnDelete(DeleteBehavior.Restrict);
    }
}

// Repository abstraction — keeps domain free of EF dependency
public interface IEmployeeRepository
{
    Task<Employee?>       GetByIdAsync(int id, CancellationToken ct = default);
    Task<IReadOnlyList<Employee>> GetByDeptAsync(int deptId, CancellationToken ct);
    void Add(Employee employee);
    Task SaveChangesAsync(CancellationToken ct = default);
}

public sealed class EmployeeRepository(AppDbContext ctx) : IEmployeeRepository
{
    public Task<Employee?> GetByIdAsync(int id, CancellationToken ct) =>
        ctx.Employees
           .AsNoTracking()             // READ-ONLY — no change tracking overhead
           .Include(e => e.Department)
           .FirstOrDefaultAsync(e => e.Id == id, ct);

    public async Task<IReadOnlyList<Employee>> GetByDeptAsync(int deptId, CancellationToken ct) =>
        await ctx.Employees
                 .AsNoTracking()
                 .Where(e => e.DepartmentId == deptId)
                 .OrderBy(e => e.Name)
                 .ToListAsync(ct);

    public void Add(Employee employee) => ctx.Employees.Add(employee);
    public Task SaveChangesAsync(CancellationToken ct) => ctx.SaveChangesAsync(ct);
}
Performance Tips
Use AsNoTracking() on all read-only queries — eliminates change-tracker overhead. Use Select() to project only required columns; avoid loading full entities for list views. Use ExecuteUpdateAsync() / ExecuteDeleteAsync() (EF Core 7+) for bulk operations without loading entities.
Common Mistakes
N+1 queries: iterating a collection and calling .Department inside the loop without Include(). Forgetting to call SaveChangesAsync(). Using Find() on un-tracked entities in read-heavy services.

C# — Minimal API with JWT
// Program.cs — ASP.NET Core 8 Minimal API
var builder = WebApplication.CreateBuilder(args);

// DI Registration
builder.Services.AddScoped<IEmployeeRepository, EmployeeRepository>();
builder.Services.AddScoped<IEmployeeService, EmployeeService>();
builder.Services.AddDbContext<AppDbContext>(opt =>
    opt.UseSqlServer(builder.Configuration.GetConnectionString("Default")));

// JWT Authentication
builder.Services
    .AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(opt =>
    {
        opt.TokenValidationParameters = new TokenValidationParameters
        {
            ValidateIssuer           = true,
            ValidateAudience         = true,
            ValidateLifetime         = true,
            ValidateIssuerSigningKey = true,
            ValidIssuer              = builder.Configuration["Jwt:Issuer"],
            ValidAudience            = builder.Configuration["Jwt:Audience"],
            IssuerSigningKey         = new SymmetricSecurityKey(
                Encoding.UTF8.GetBytes(builder.Configuration["Jwt:Key"]!))
        };
    });

builder.Services.AddAuthorizationBuilder()
    .AddPolicy("HROnly", p => p.RequireRole("HR", "Admin"));

var app = builder.Build();
app.UseAuthentication();
app.UseAuthorization();

// Endpoint group
var employees = app.MapGroup("/api/employees")
    .RequireAuthorization()
    .WithTags("Employees");

employees.MapGet("/", async (IEmployeeService svc, CancellationToken ct) =>
{
    var result = await svc.GetAllAsync(ct);
    return Results.Ok(result);
});

employees.MapGet("/{id:int}", async (int id, IEmployeeService svc, CancellationToken ct) =>
    await svc.GetByIdAsync(id, ct) is { } emp
        ? Results.Ok(emp)
        : Results.NotFound());

employees.MapPost("/", async (
    CreateEmployeeRequest req,
    IEmployeeService svc,
    CancellationToken ct) =>
{
    var created = await svc.CreateAsync(req, ct);
    return Results.CreatedAtRoute("GetById", new { id = created.Id }, created);
})
.RequireAuthorization("HROnly")
.WithRequestValidation<CreateEmployeeRequest>();

app.Run();
Best Practices
Never put business logic in controllers — they are HTTP adapters only. Register services with the correct lifetime (Transient for stateless, Scoped for per-request like DbContext, Singleton for caches). Always return typed results (Results.Ok(), Results.NotFound()) not raw objects.
Security Recommendations
Never store JWT secret keys in appsettings.json — use Azure Key Vault or environment variables. Enable HTTPS-only, CORS strictly, and rate limiting (AddRateLimiter) on all public endpoints. Validate all input with FluentValidation or Data Annotations before processing.

C# — SOLID / Clean Architecture Snippet
// SOLID — Single Responsibility + Open/Closed + DI
// Each class has one reason to change.

// Domain Layer — no framework dependencies
public sealed class Order
{
    public Guid   Id         { get; private set; } = Guid.NewGuid();
    public List<OrderItem> Items { get; } = [];
    public OrderStatus Status    { get; private set; } = OrderStatus.Draft;

    public void AddItem(Product product, int qty)
    {
        if (Status != OrderStatus.Draft)
            throw new DomainException("Cannot modify a submitted order.");
        Items.Add(new OrderItem(product, qty));
    }

    public void Submit() => Status = OrderStatus.Submitted;
}

// Application Layer — CQRS Command Handler (MediatR)
public record PlaceOrderCommand(Guid CustomerId, List<OrderItemDto> Items)
    : IRequest<Guid>;

public sealed class PlaceOrderHandler(
    IOrderRepository orders,
    IProductRepository products,
    IPublisher publisher) : IRequestHandler<PlaceOrderCommand, Guid>
{
    public async Task<Guid> Handle(PlaceOrderCommand cmd, CancellationToken ct)
    {
        var order = new Order();
        foreach (var item in cmd.Items)
        {
            var product = await products.GetByIdAsync(item.ProductId, ct)
                ?? throw new NotFoundException(nameof(Product), item.ProductId);
            order.AddItem(product, item.Quantity);
        }
        order.Submit();
        await orders.AddAsync(order, ct);
        await publisher.Publish(new OrderPlacedEvent(order.Id, cmd.CustomerId), ct);
        return order.Id;
    }
}

Best Practices
Keep your domain layer free of all framework and infrastructure dependencies. Use MediatR for CQRS to decouple commands from handlers. Validate at the application boundary (FluentValidation pipeline behaviour) not inside domain entities. Never reference EF Core from the domain layer.
Interview Tips
SOLID: be able to give a concrete code example for each principle, especially the Liskov Substitution Principle (the "square is a rectangle" problem). For DDD: know Aggregate Root, Bounded Context, and Domain Events. For Microservices: discuss eventual consistency, saga pattern, and distributed tracing.

What is the output of 5 / 2 in C# with both operands as int?
2.5
2
Error

Which LINQ method defers execution until enumerated?
ToList()
Where()
Count()

Where(), Select(), OrderBy() are deferred. ToList(), Count(), First() are terminal/materialising.

What's the difference between RANK() and DENSE_RANK()?
No difference
RANK() skips numbers after ties; DENSE_RANK() doesn't
DENSE_RANK() resets per partition

If two rows tie at rank 1, RANK gives the next row rank 3. DENSE_RANK gives it rank 2 — no gaps.

What does AsNoTracking() do in EF Core?
Disables lazy loading
Prevents inserts
Removes change-tracker overhead for read-only queries

EF won't snapshot or track the entities returned, reducing memory and CPU overhead significantly on read-heavy endpoints.

Frequently Asked Questions

Common questions from developers learning the .NET stack.

What is the difference between IEnumerable<T> and IQueryable<T>?
IEnumerable<T> executes LINQ in memory (LINQ to Objects). IQueryable<T> translates the LINQ expression tree into SQL via EF Core's query provider — the database does the filtering, not your application. Always use IQueryable with EF Core and only call ToListAsync() at the last moment to avoid loading unnecessary data.
When should I use a stored procedure vs EF Core LINQ?
Use EF Core LINQ for most CRUD and simple queries — it's maintainable and testable. Use stored procedures for complex reporting, bulk operations, or where DBA-controlled query plans matter for performance. You can call stored procedures from EF Core using FromSqlRaw() or ExecuteSqlRawAsync().
What is the N+1 query problem and how do I fix it?
N+1 happens when you load a list of entities (1 query) and then access a related navigation property inside a loop (N queries). Fix it with EF Core's .Include() for eager loading, or use Select() to project a flat DTO in a single query. Use MiniProfiler or SQL Server Profiler to detect it.
How does JWT authentication work in ASP.NET Core?
The client sends credentials to a login endpoint; the server validates and returns a signed JWT (header.payload.signature). On subsequent requests, the client sends the token in the Authorization: Bearer <token> header. ASP.NET Core's JWT middleware validates the signature and claims on every request — no server-side session storage needed.
What is Clean Architecture and why does it matter?
Clean Architecture (Uncle Bob) organises code in concentric layers: Domain → Application → Infrastructure → Presentation. The dependency rule: inner layers never reference outer ones. This makes the domain and application logic testable without a database or HTTP framework. It matters at scale because it keeps business logic isolated from infrastructure churn (ORM upgrades, cloud migrations, etc.).
